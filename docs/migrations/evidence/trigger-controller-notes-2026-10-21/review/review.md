## 4. Architecture and operational safety

The existing sealed authority boundary remains the sole request authority. Mutable public correlation fields alone cannot authorize another attachment/instance. The controller remains constructing-thread `!Send/!Sync`; fixed arrays bound metadata. Neither browser time nor wall-clock work reaches audio. Note lifetime uses existing runtime intent and cleanup instead of the ordinary event queue, and does not reset scalar settlement/history or worker jobs. Successful restore clears controller note metadata only after accepted runtime/session commit. Unknown Off cannot release another owner, and original generations survive ordinary mapping/undo.

Rejected stale-generation and owner-conflict commands validate before expiry; the genuine REDs and signed regression tests protect that ordering. Backward dispatch consumes its transport identity but does not renew activity. A qualified edge remains: runtime sequence exhaustion can occur after trusted service has advanced the monotonic watermark or expired old leases. It cannot accept a new press or renew activity. Therefore this review does not claim every `Err` preserves every note-policy field. That distinction is explicit in portable evidence/progress and consistent with the accepted contract.

Reset suppresses pre-reset runtime sequence without clearing controller press ownership. Heartbeat cannot advance the sequence and therefore cannot revive audio; a fresh On can. The wire has no physical press nonce, and no stronger same-generation old-release discrimination is claimed. Slot reuse and release invariants follow from exclusive controller ownership and sealed ranges; the runtime Off invariant is not a hidden competing-author path.

Resource evidence preserves the stopped attempt and subsequent disk-only success. ## 5. Better alternatives

No materially simpler in-scope design preserves the contract better. Fixed pitch/attachment arrays fit the hard domain bounds and avoid another allocation/journal system. The private note-command enum makes post-authentication cases exhaustive; retaining policy in the existing controller avoids a new module whose only purpose would be test access. Moving timeout decisions to audio violates the accepted callback boundary; tying them only to browser heartbeat loses cleanup after editor failure. Clearing replay watermarks on expiry or restore permits re-arming retained On requests. Dropping original press generations breaks releases across real mapping/undo. Existing narrow public APIs and sealed context provide the appropriate reuse; no new token, wire nonce, general replay cache, executor or dependency is warranted.

## 6. Reusable lessons

The narrow owner is this controller test/design, where the correction already lives. No new global rule is proposed; the shared behavior and independent-oracle guidance already covers it.

The coverage corrections reinforce reading the actual child environment and comparing semantic counters separately from tool metadata/float serialization. Existing evidence-binding guidance already owns that principle. Retain these concrete receipts, without adding standing guidance or memory.
