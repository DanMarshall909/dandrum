Realtime, race and ownership assessment

- The gate uses one AtomicU64. Callback CAS 0→ACTIVE and control fetch_or(CLOSED) are ordered on the same atomic: either a callback was admitted and control waits for its release, or CLOSED wins and callback does not enter. Waiting/yielding occurs only off audio. Callback exit clears ACTIVE while preserving CLOSED. Release reopening follows queue publication. Acquire callback admission observes it. Rust's exclusive `&mut RuntimeAudio` prevents concurrent safe access to the mutable DSP endpoint.
- The lease borrows the control fields. No second control operation can race it. A cancelled lease frees only its candidate off audio; accepted session/runtime remain unchanged. Successful session installation stages the next snapshot/history before activation, replaces accepted state while admission is closed, then calls infallible publish. Candidate construction and layout errors occur before close/publication.
- Reservation of a retirement slot precedes `pending.pop()`, so no popped runtime needs a failure/drop fallback on audio. Safe rtrb 0.3.2 chunk APIs were inspected: write-slot reservation, move/read, and one-element publication do not clone/destroy owned runtimes or allocate. The in-flight flag clears only after `reclaim` pops retirement. Control-drop-first retains the other queue endpoint on audio, so reference-count destruction is deferred to endpoint teardown.
- Process performs no Arc cloning, mutex/RwLock acquisition, file access, JSON work or resource resolution. DSP/scratch ownership is stable. Vec resize stays within construction-time capacity even after short blocks. Full stereo planes are filled/copied. Realtime schedule probing and reset happen at construction; script-only root schedules are refused, and engine preparation rejects unsupported poly child schedules. The tested platform is Linux x86_64 with native 64-bit atomics.
- Each queued source is bounded by configured event capacity and a callback drains at most that capacity even if the producer concurrently refills it. A host slice larger than that bound is rejected. Capacity is at most half the engine's pending capacity, so simultaneous queued and host note batches fit; the engine derives capacity from fixed block settings. Host offsets are implemented by rendering ordered subsegments then applying events at segment offset zero; the final offset must be strictly inside the block, leaving a nonempty tail. Equal-offset events retain supplied order.
- Input shape, count, offset ordering and every event/value are validated before replacement, queue consumption or scalar changes. Invalid callbacks overwrite outputs with silence while preserving pending accepted work. Layout compatibility makes validating against current ports before a swap sound. Feedback overflow has an explicit count and atomic recovery path instead of pretending all events were delivered.
- Endpoint destruction is intentionally an adapter lifecycle obligation: stop callback access, return RuntimeAudio, then destroy off audio. The module cannot prevent a future adapter from dropping its owned endpoint on an audio thread. Actual CLAP stop/return wiring is task 4.1, not claimed by this review. Closed reset is a deliberate no-op until the lease releases; tests pin that behavior.
