## Architecture, safety and alternatives

The format-neutral host remains independent of Clack/GUI/device types. The adapter's immutable public metadata copies are not a second authoritative scalar vector; scalar reads/writes converge on runtime atomics. Activation validates first, takes the parked endpoint, restores it on every Result failure, explicitly services returned ownership, and reconfigures through the accepted paired controller operation. Deactivation returns the same endpoint without a controller borrow. The explicit error branch is sufficient for the current fallible paths; introducing a generic ownership abstraction would add machinery without a demonstrated safety benefit.

Process performs complete event translation before entering runtime mutation. The preallocated 64-entry buffers bound supported event work. Invalid output cleanup intentionally scales with available host-declared planes; it is not claimed fixed under arbitrary malformed layouts. Pointer validity remains the CLAP/Clack boundary contract. Shared diagnostics use atomics/static strings; host callbacks may have their own behavior, so the calibrated recorder limits the allocation claim appropriately.

State input is bounded to 65,537 bytes before controller access; the existing 65,536-byte codec and resource identity policy validate before publication. Output serialization is bounded by the existing codec and is completed before calling host output streams. Owned input buffering and released borrows avoid the reentrant-stream RefCell panic. The resource path is explicit and private; current state validation retains the recognized sample source and frozen public surface. No new network/file-selection authority, secret material, unsafe production code or GUI dependency was introduced.

The most tempting alternative, rounding a floating host sample rate to u32, would silently lie about time and is not an acceptable compatibility fix. Genuine fractional support is a separate cross-owner design decision. Rebuilding the session on every activation or keeping a second parameter vector would be simpler locally but would violate persistence/single-authority requirements. A direct use of Clack's allocating error path in rejected audio callbacks would defeat the callback contract. The chosen narrow projection is appropriate; no materially better in-scope design requiring replacement was found.
