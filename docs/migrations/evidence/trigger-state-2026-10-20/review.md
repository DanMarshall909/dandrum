Atomicity, callback and resource assessment

Exclusive mutable controller ownership prevents concurrent accepted-document replacement during save/load; audio alone can race scalar reads. For the coherent vector, every participating data/stamp access is SeqCst. Equal even stamps bracket a global atomic order without an intervening writer, subject to the explicit 2^63 complete-write wrap limit. Restore writers are serialized against callback writers by admission. Only save loops/yields; audio adds two fixed fetch_add operations and scalar stores. Reader progress under a continuously active writer is not bounded and is disclosed, rather than claimed as a latency guarantee. Ordinary UI snapshots retain their conservative settlement semantics.

The lease fully prepares the realtime candidate and reserves pending storage before accepted mutation. Closing admission waits on the control thread for a previously admitted callback. Its release/acquire handoff makes the relaxed epoch accesses safe within the single controller and admitted audio domains; no callback can see the new candidate with old restored scalars. Values and epoch are paired in RestoredScalars. Invalid input never reaches this publication point. Reclamation before a later attempt may release an already retired processor, but cannot alter the accepted document, active processor, scalar values or pending useful work on failure.

Resource checks inspect typed root/registry defaults and literal node arguments, not YAML text. Exactly the packaged source identity and document-relative sample path are allowed; locality is checked again before Session preparation. The Session's macro roots are empty, so external module references cannot silently resolve an unvalidated package through a source/CWD fallback. Root layout compatibility prevents a successful candidate from changing the runtime's indexed parameter meaning. No Clack, WebView, JUCE, new dependency or unsafe code enters this owner.

The callback retains bounded queue loops, safe preallocated ownership transfer and no resource reclamation, serialization, file access, browser access, blocking or allocating code. Pending/retired processor destruction remains off audio. The inherited ClosedAdmission path still deliberately returns silence while publication holds the lease. These tests prove coherent transition and callback memory safety, not uninterrupted native lifecycle audio. That limitation is explicitly retained in progress/evidence and later tasks; it is not a new in-scope failure.

Alternatives and lessons

Reusing the prepared Session transaction is materially simpler than a second state authority or editor-created native attachment. Epoch tagging preserves SPSC ownership; draining audio-owned queues from main would violate it. Locking or closing callback admission for save would add audible interference; a coherent off-audio stamped read is justified by the actual mixed-vector RED. The private codec/resource policy extraction keeps controller orchestration small and is fully measured. No extra abstraction or general schema migration machinery is needed. Version 2 is the accepted replacement format, with no speculative old-state migration.

No new standing-guidance change is proposed. The strongest demonstrated lessons—literal independent DSP/resource oracles, source-bound coverage, setup-failure separation, and honest GREEN characterization—are already owned by the project/shared testing rules. The known structural silence gap is retained as a later native acceptance obligation rather than hidden or reclassified as completion evidence.
