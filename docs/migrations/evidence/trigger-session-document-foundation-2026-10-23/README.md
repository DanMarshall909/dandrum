# Session document history and resource ownership

This focused boundary advances the CLAP beta's tasks 5.1–5.3 without closing a task or scenario. The format-neutral session accepts trusted whole-document jobs through the existing preparation/publication pipeline, keeps exact native Undo/Redo and request outcomes across editor loss, and owns selected content alongside each accepted or historical document. No editor capability or portable-state completion is advertised here. CLAP protocol/controller/GUI changes remain separate unpublished work. VST3 and standalone stay deferred.

The session now publishes the document, prepared instrument and preparation context atomically. Document history retains shared YAML and immutable selected sample owners rather than prepared DSP instances. Mapping entries preserve their existing delta metadata; document entries carry truthful document metadata. Both use the existing 100-entry journal, one pending job and 128 terminal outcomes. Exact retries are checked before resolving resources, so losing a view or releasing selection authority cannot force already admitted work to acquire it again. Preparation always replaces a historical context's clock with the current precise session clock.

A separate real bug in external replacement retained every old selected owner indefinitely. The candidate now derives its required selected context from sample sources and static resource references/defaults. Failure preserves the previous complete state; successful publication releases omitted owners after remaining runtime/history owners retire. The engine exposes a borrowed iterator over immutable owners for this derivation. No decoder, callback, queue, dependency or C ABI layout changes are introduced.
