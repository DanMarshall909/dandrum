## Context

The existing `dandrum_clap_adapter` is a JUCE-free, dynamically loaded CLAP binary with proven audio, MIDI, parameter, state and lifecycle behavior for two embedded fixture documents. It has no GUI and prepares its runtime directly from fixture text. The completed `dandrum_instrument_session` crate owns accepted sampler YAML, preparation, bounded native history, disposable attachments and atomic activation, while the production Trigger bundle currently obtains native functions and events through a JUCE-specific JavaScript object.

The selected proof platform is Linux x86_64 with X11 parenting and WebKitGTK 2.50.4. Clack already exposes the CLAP GUI extension at the pinned repository revision, and the investigation selected Wry 0.57.0 as the first child-WebView backend. The render callback must remain free of locks, allocation, file I/O, serialization, browser access and resource reclamation.

## Goals / Non-Goals

**Goals:**

- Add one real Trigger sampler identity to the JUCE-free CLAP binary, using the persistent session and existing Rust engine.
- Run the production Trigger bundle as an actual X11 child of a host-owned window and event loop.
- Keep the editor disposable while accepted session state, admitted work, native history and audio survive.
- Translate one real Trigger parameter gesture to CLAP automation and return host parameter feedback to React.
- Exercise a native mapping edit and undo through the same session implementation already used by the comparison host.
- Prove signed sample rendering, state restore, lifecycle failures and independent instances from a copied artifact/resource tree outside the checkout.
- Leave a format-neutral host core suitable for the following VST3 and standalone projection.

**Non-Goals:**

- VST3 wrapping, standalone audio/MIDI device ownership, named-DAW acceptance or installed release packaging.
- Wayland, Windows or macOS editor support in this increment.
- Full migration of every Trigger editing command, analysis service or telemetry stream.
- Retaining unreleased JUCE product/state/parameter identities.
- Changing DSP algorithms or using a WebView from the render callback.

## Decisions

### Separate the format-neutral Trigger host core from CLAP and Wry adapters

Add a focused Rust host crate that owns the instrument session, versioned editor protocol, public parameter model and runtime handoff. Its core modules contain no Clack, Wry, GTK, X11 or JUCE types. CLAP and Wry modules adapt their concrete lifecycle and handles at the edge. This gives the next VST3/standalone change one tested owner instead of copying CLAP policy.

Extending the fixture-only adapter directly would be initially smaller, but it would entangle session, GUI and CLAP types and force the format projections to repeat that work. Adopting Nice-plug now would discard the already proven Clack binary before the selected route has failed a gate.

### Keep session ownership off audio and transfer prepared runtimes through bounded slots

The main-thread host owns `InstrumentSession`. Activation constructs the next realtime processor and all scratch buffers off audio, then offers the owned runtime through a capacity-one nonblocking handoff. At a block boundary the audio processor swaps the pending runtime and returns the retired runtime through a preallocated reclamation slot; only the main thread destroys it. One in-flight replacement keeps capacity provable and maps naturally to the session's one admitted structural job.

Atomics carry scalar parameter values. Bounded single-producer/single-consumer queues carry parameter events, runtime replacements and acknowledgements. No mutex or reference-count destruction is permitted in `process`.

### Service an accepted runtime while its audio endpoint is inactive

Task 4.1 first adds a narrow format-neutral quiescent service operation. The caller must hold exclusive mutable borrows of the matched control and returned audio endpoints, with no audio callback running. Private endpoint identity is checked before any mutation; a foreign pair is rejected with both instances unchanged. This is a boundary between audio blocks while inactive, not a fabricated render call or a second session publication path.

One bounded call reclaims at most one already-retired runtime and adopts at most one already-accepted pending runtime, destroying predecessors on the calling control thread and restoring activation capacity without waiting for a future audio block. Repeated idle service is a no-op and an explicit report distinguishes adoption and reclaimed/destructed count. Running audio retains its capacity-one block-boundary swap and reclamation handoff. Scalar values, settlement/epoch, queued events, configuration and layout remain intact. Adoption follows the same editor-intent law as a real block-boundary swap: held intent may resume on a subsequent actual block, released/cancelled onsets cannot replay, and host arbitration has no new voice-resumption promise.

Public signed-audio, cross-thread ownership and callback/destructor sentinels must prove pending and already-retired paths, foreign-pair failure atomicity, independent instances, repeated idle service, preserved queued scalars/notes and immediate capacity for a second offer without a fake render. No controller, rate/configuration, stopped-flush or native CLAP behavior is claimed by this runtime prerequisite. Those remain subsequent task 4.1 boundaries, and the complete editor/beta tasks stay open.

### Reconfigure the persistent session only with returned audio ownership

Task 4.1 next exposes the controller-owned route to paired quiescent runtime service and a separate atomic render-configuration operation. The service route forwards the existing private endpoint to the accepted paired service; it does not service jobs, expire notes, flush values or change document generation. Public tests must close the prior observer gap using nonzero applied/admitted UI sequences and a nonzero restore epoch, including a revision different from that epoch. No private counter or test-only command is introduced.

Render reconfiguration takes exclusive mutable borrows of the controller and its matched returned audio endpoint. Reject a foreign pair before any mutation, even when another error also applies. Validate the inherited integer configuration bounds (positive rate and maximum block size 1 through 16,384), then reject any queued/preparing/ready structural job or in-flight runtime ownership as Busy. Do not collect a completion, reclaim, adopt, cancel or wait during this failure path. Callers may separately perform bounded service and retry. No actual host retry behavior is claimed. An equal complete configuration returns an explicit unchanged result only after these checks, without reading resources, reconstructing DSP, allocation or destruction.

For a changed configuration, expose the existing owner-authorized Session render-preparation operation intentionally, following its document-replacement owner API. Derive equivalent named planar buses from the accepted document. A narrow quiescent activation host/lease constructs the full runtime and scratch during activation, before the Session commit point, and validates layout, public surface and retained event capacity. The graph budget is max(maximum block frames, 128); existing event capacity E must still satisfy 2E <= budget. Reject an unsupported shrink without rebuilding endpoints or changing any accepted field. Once all preparation succeeds, publication installs Session preparation/settings/context and the runtime/control configuration infallibly; the replaced runtime is destroyed on the calling control thread. Dropping an unpublished candidate/lease preserves the previous configuration and accepted state.

Pure render reconfiguration preserves accepted YAML, revision, journal/cursor, outcomes, native attachment/request identities, descriptors, document generation, gestures/reserved Ends, public values, applied/admitted UI sequences and reset cause, feedback, queued work, restore epoch and editor press/watermark/activity records. Keep the original endpoints, slots and atomics. It neither replaces the authoring document nor creates an undo step. New DSP replaces prior voices/tails; editor intent follows the already accepted adoption law: held intent can resume on the next real block, released/cancelled/reset onsets cannot replay, and host-held pitch arbitration remains without a new host-voice-resumption promise. Preparation may reread current packaged resources under the retained context; no new hot-resource-reload promise is made. Failed resource preparation preserves the old loaded runtime.

Public behavior tests cover same-configuration continuation, changed rate and maximum block size, retained-capacity shrink rejection, foreign independent instances, all structural work states and pending/retired runtime Busy, corrupt/missing resource failure, accepted history/outcomes and real undo, nonzero epoch/sequence/reset cause, feedback/automation/held gesture preservation, authenticated editor notes, actual cross-thread ownership return and callback allocation/destruction sentinels. Signed waveform assertions must distinguish 48,000 Hz from 44,100 Hz using multiple independently derived PCM/interpolation samples and nonzero onset offsets; the common first sample alone is insufficient. A later structural edit must use the new preparation settings, proving Session and runtime agree. Preserve the separate ordinary-note FIFO evidence rather than adding a controller note-injection seam. Stopped parameter flush, native floating-point host conversion, actual CLAP activation/retry and installed/native acceptance remain subsequent boundaries; task 4.1 and the beta stay open.

### Flush scalar parameters without advancing audio

After the task4.1 render-configuration prerequisite is verified and published, add a separate format-neutral RuntimeAudio::flush_parameters(&mut self, host: &[ControlEvent]) -> Result<ParameterFlushReport, RuntimeError>. The report contains admission_closed, parameter_updates, dropped_feedback and deferred_at_note. Host input is a bounded parameter-only batch; validate its entire count (<= retained E), kinds, indices, finite f64 and f32-convertible physical values and ranges before admission or state changes. Invalid input returns InvalidEvent even if admission is closed. Valid denied admission returns an otherwise-default report with admission_closed=true, without waiting, queue inspection or a scalar-write interval. Preserve existing process admission/validation precedence unchanged.

An admitted flush uses the established scalar-write interval and inspects at most E queued UI entries, including obsolete scalars and concurrent refill. This is an observed bounded prefix, not an entry-time snapshot. Before checking epoch, stop at any ordinary NoteOn/NoteOff, leave it and its suffix queued and report deferred_at_note. Only obsolete scalar-prefix entries may be discarded; current scalars apply in FIFO order with their retained sequence. Then apply validated host values in order at offset zero, including duplicates. Count every applied scalar and every failed bounded feedback push, retaining recoverable latest atomic values. Host-only writes preserve prior UI settlement/reset cause; only an actually applied UI command acknowledges its sequence. deferred_at_note=false does not promise an empty queue when E inspections are exhausted.

For queued [P1, Note, P2] plus host H, flush applies P1 then H and retains [Note, P2]. Repeated flush cannot let P2 overtake Note. The next real process may apply P2 after H; flush/process interchangeability is not claimed. Do not render, reset, evaluate editor intent, enqueue graph notes, adopt/reclaim a runtime, read resources, allocate or destroy resources in this callback boundary. Preserve graph position/tails, pending replacements, ordinary note order and unrelated instance state.

First characterize current process FIFO/order with signed output, then retain behavior RED/GREEN/focused LLVM for complete-batch rejection atomicity; admission denial; scalar/UI/host ordering and feedback/overflow; current and stale note barriers; bounded stale-prefix/refill work; genuine nonzero controller sequence/reset cause/save/get/history and actual later once-only signed note playback. Use public runtime handoffs for ordinary note tests, no controller note injector. Existing internal paused restoring-lease fixtures may deterministically specify the public flush denial result; do not claim that fixture is a public-only path or add a production gate hook. Extract a shared infallible scalar helper only after existing process behavior is covered, keeping caller ordering/admission/budgets unchanged and proving every new helper region.

This is a standalone core prerequisite, not automation output delivery, a new queue topology, native CLAP event policy or native scheduling. Keep task4.1/4.2 and full-beta checkmarks open. Final owner tests/docs, formatting, strict Clippy, source-bound LLVM/profiles, independent review and a normal focused commit/publication precede following implementation. Mutation stays excluded; release/native product proof remains at the actual facade/final gate.

### Project the persistent Trigger session into the actual CLAP product

After the stopped-flush prerequisite is normally published, task4.1 adds a separate opt-in TriggerAdapter at the pinned Clack revision. Cargo default features remain empty and the default binary retains the two unchanged fixture identities. The trigger feature adds org.dandrum.trigger, named Dandrum Trigger, vendor Dandrum, version0.1.0, instrument/sampler/stereo. Its replacement identity matches version2 Trigger state. Descriptor enumeration does not read sample resources. Trigger initialization requires the absolute Linux plugin-file path supplied to Entry, retained with OS bytes, and resolves only its sibling DandrumTrigger.resources; no cwd, executable or checkout fallback. An unusable path or missing resources fails Trigger initialization without disabling fixture descriptors.

The CLAP main owner keeps one persistent ParameterController behind a RefCell and one primary Cell<Option<RuntimeAudio>> parked slot outside that borrow. Deactivate returns the same owned endpoint to this slot without borrowing the controller; activation uses a scoped ownership rollback guard so errors cannot discard a taken endpoint. Open once with provisional48000Hz/max16, event capacity64 and automation capacity256. Shared/audio metadata is immutable; there is no duplicate authoritative scalar vector. A narrow public-index physical-value accessor forwards the controller alias's root index to existing runtime atomics, returning None for unknown indices. CLAP IDs1..23 follow frozen public alias order, with physical bounds/defaults and global automatable values. Activate rejects nonfinite, nonpositive, fractional or out-of-u32 rates and invalid min/max blocks (max<=16384), explicitly services returned runtime ownership then atomically reconfigures that same pair before moving audio out. Failure retains the parked owner; deactivate returns the same endpoint. Reentrant main borrow conflicts fail/defer explicitly, never panic. Release main borrows before foreign host calls; audio callbacks never borrow Main.

Expose one float32 stereo output, no audio input and one MIDI1 input, retaining the fixture's declared MIDI dialect. Process validates the complete at-most64-event list before semantic mutation: all header offsets are nondecreasing and inside the block; supported MIDI note messages require port0 and7bit note/velocity; NoteOn velocity0 is NoteOff. Global parameter values require frozen IDs, all-target PCKN and valid finite f64/f32-convertible physical values. Wellformed unsupported event kinds and unrelated MIDI messages are ignored within the same finite input budget. A recognized malformed supported event rejects the whole batch, preserving accepted values, queued work and DSP progress. Active/stopped parameter flush translates only parameter values, ignores wellformed unrelated event kinds within the finite list budget, ignores flush timestamps and applies the established zero-offset scalar-prefix law. Unsupported modulation, per-note automation, float64 audio and GUI are not advertised in this headless slice.

Invalid process calls silence available writable outputs and return supported Continue with a bounded atomic diagnostic reason; they do not return Clack's allocating error/logger path or forge a raw error status. Active flush rejection similarly preserves scalar/queue state. The callback requests main service through a valid-lifetime host handle; on_main_thread consumes the bounded reasons and reports static diagnostic codes through optional HostLog after releasing core borrows. Host logging availability and callback delivery are host capabilities; no delivery without an entrypoint or arbitrary-host allocation guarantee is claimed. Valid callback paths remain lock/allocation/deallocation/I/O/serialization/browser free. Actual dynamic-plugin/framework allocation evidence must observe the cdylib allocator with a calibrated preallocated host recorder/logger; a host-only Rust allocator sentinel is insufficient.

CLAP state delegates bounded version2 save/load to the same controller. Host InputStream reads and OutputStream writes are foreign callbacks: read a complete size-bounded owned input before borrowing the controller, and serialize to bounded owned output under the borrow before releasing it and writing to the host. Loading from the owned buffer retains the existing atomic validation/publication contract. No host stream is called while a controller borrow is held. Invalid streams/state preserve accepted document, values and signed audio. Successful inactive load services accepted runtime ownership explicitly; active load adopts on a real block. Rescan/notification happens after releasing the core borrow. Dynamic tests use copied release artifacts/resources outside checkout and independent literal signed PCM, nonzero offsets, exact nondefault physical values, fresh changed-mapping restore, invalid state/batch rollback, reset, failed/successful reactivation and actual cross-thread audio ownership with independent instances. Keep the existing default fixture tests intact and separate. The GUI, worker/GLib service, browser method join and outbound gesture mirror remain task4.2/3.3; do not introduce an unused private mirror or copied-ledger API in this slice.

The opt-in CMake target stages DandrumTrigger.clap with three descriptors beside existing resources; default DandrumHeadlessProof.clap keeps two. Reuse warm Cargo output with an explicit dependency chain serializing feature build and artifact copy, so parallel feature builds cannot overwrite the source library during copy. Root owns CMake/source-free fixture wiring; the adapter author owns Rust and dynamic tests. Verify the actual combined source-free build with no JUCE/source lookup and inspect linkage/resource hashes before completion. Reuse only unchanged source-bound baseline evidence; current release/native claims need current binaries. Strict formatting/Clippy, owning tests/LLVM/profile bindings, independent review and normal focused publication remain required. Mutation stays excluded and caches preserved. The100% extraction rule applies to newly extracted modules; new feature code must meaningfully cover reachable behavior and explicitly qualify defensive invariant paths without fabricated counters/seams/unsafe coverage tricks. Task4.1 is completed only after its whole product proof passes; editor/native/full-beta tasks remain open.

### Use a versioned local editor protocol and transport-neutral JavaScript backend

The Trigger native adapter selects a `window.__DANDRUM__` backend contract with an explicit protocol version. The existing JUCE bridge supplies the same contract for comparison builds. The Wry adapter serves the production build and packaged fonts through an application-local scheme and exchanges bounded request/reply/event JSON with monotonically increasing request IDs. Unknown methods, malformed payloads, oversized messages and stale attachment IDs receive explicit errors.

The initial JUCE-free method set is deliberately the subset required for session snapshot, public parameter gestures/feedback, note ownership, key-range mapping, job outcome recovery and native undo. Existing unsupported operations continue to report capability limits; the frontend never simulates native acceptance.

### Declare optional editor services without fabricating native success

The bootstrap descriptor may include `capabilities` with strictly boolean `metering`, `sourceWaveforms`, `windowTitle` and `editorResize` fields. An omitted profile or field preserves the existing full-contract behavior for every backend identity, including existing version-1 `juce-free` descriptors. The legacy JUCE selector and explicitly injected comparison backend retain their behavior. Present invalid metadata fails visibly before invoking native methods; backend names never imply service availability.

The new Wry bootstrap explicitly declares those four services unavailable. This is local bootstrap metadata, not another protocol method. Session snapshot, parameter gestures/feedback, note ownership/heartbeat, supported mapping, job recovery and native undo remain real required services. No successful meter subscriptions, measured values, waveform jobs or resize acceptance are invented.

The frontend gates absent services during initialization, generation refresh, mapping/undo, rendering and disposal. Heartbeat and note cleanup remain independent of metering. It shows unavailable meters, unknown active voice count, an accessible unavailable-waveform state and host-controlled size; it supplies no generated preview peaks or fake silence measurements. Direct requests for absent waveform service return an explicit capability error without native mutation. Supported-service failures retain their existing errors and retry behavior.

### Keep editor note intent bounded and arbitrate pitch ownership on audio

Retain the existing wait-free bounded SPSC event handoff and its explicit QueueFull result for ordinary queued note/parameter events. Editor keyboard notes additionally use a fixed 128-pitch native intent table, constructed off audio. One main-thread producer records the held attachment and last publisher; the controller will retain the document generation recorded for each press. Each atomic word publishes a checked onset sequence, retained onset velocity and desired velocity coherently. A conflicting editor owner, invalid note/velocity or exhausted sequence returns an explicit runtime error. Native attachment authenticity and document-generation validation belong to the controller, rather than this trusted-owner runtime API. Repeated same-owner presses may coalesce before audio; accepting intent does not promise voice allocation. Ordinary release preserves an unheard drum tap. Detach clears both desired and retained onset for its last-published rows, including an already released tap, without needing queue capacity or affecting a newer attachment.

The callback performs only finite scans and atomic loads; it never waits for a producer, locks, allocates, destroys resources or calls a browser. Audio-owned pitch state distinguishes accepted editor gates from host-held pitches. Host note-on takes over a same-pitch editor gate before its own onset; editor release/detach never releases that host gate. Host-held or host-touched pitches suppress editor onsets, and a still-desired editor intent may resume on a later untouched block after host release. A new onset or reconnect cannot precede successful release of the previous editor gate. Failed or budget-deferred releases retain their obligation. An unheard cancelled tap cannot start later. This is pitch arbitration over the existing engine, not independent source-tagged simultaneous voices.

Reserve graph-event capacity for all validated timed host events and their possible editor takeover releases. Service retained cleanup before draining ordinary queued events or starting editor notes; defer bounded queued work when editor cleanup consumes its graph-event budget. Each accepted graph note operation uses the checked engine enqueue result. Shared takeover/cleanup release credit is counted once, with a bounded fair pitch scan. Normal callbacks without editor work retain the established queue behavior. Prove saturation using the actual graph capacity and a representative gated sample child with literal stereo prefix and sustained signed tails; a naturally ending one-shot is not a release oracle. One-shot release must keep its natural sample tail.

New editor onsets require the current document generation; a matching held release uses its recorded press generation. The existing wire carries a document generation, not a unique physical press nonce; the controller must not claim stronger same-generation release discrimination. An ordinary mapping swap may resume a still-desired physical pitch on the new graph, while an already released/cancelled onset is not replayed. Panic reset discards pre-reset onset/voice activity and suppresses its resumption until a new press. Successful external state restore clears prior editor intent along with existing queued activity; failed restore preserves it. Explicit detach before callback observation cancels unheard work; a racing already observed onset is cleaned on a subsequent eligible callback, without synchronous waiting. Heartbeat scheduling and semantic editor disposal must later join the concrete format facade; this shared-owner component alone does not complete task 3.3.

### Authenticate note presses and expire native activity independently of the editor

The controller accepts the existing noteOn, noteOff and noteHeartbeat commands through the same sealed admitted context as parameters, snapshots and structural work. A public off-audio note-dispatch method and bounded note-service method receive native Instant values from the host; browser input never supplies time. Keep fixed metadata for 128 pitches and at most the native limit of 16 active attachments. Each pitch records its accepted owner and press document generation. A new press requires the current generation and quantizes normalized velocity once with round(clamp(value, 1/127, 1) * 127). Record press ownership and activity only after the runtime accepts intent. A release matches the recorded owner and press generation, including after mapping/undo; an old generation cannot release a newer press. Unknown release may be an idempotent no-op. The wire still has no physical press nonce, so same-generation old-release discrimination is not claimed.

Each valid attachment retains a processed note-transport watermark until actual detach. Redispatched or overtaken note requests reject rather than retrigger or renew activity; a semantic rejection is terminal for that transport ID. The facade dispatches note commands in order. Expiry and successful state restore clear press/activity state but retain this watermark for a still-valid attachment, preventing replay of an earlier admitted onset after cleanup. There is no second structural outcome journal.

Use the existing two-second native timeout, expiring at activity age greater than or equal to two seconds. Store last activity and compare checked_duration_since rather than constructing an overflowing future Instant. Reject backward service/dispatch time without changing activity. Service expiry before heartbeat renewal; heartbeat renews only an existing active lease and cannot re-arm expired/reset intent. Matching release may renew cancellation grace for an unheard tap. Duplicate or rejected commands do not extend activity. Authentication and command validation precede request-driven policy changes; trusted periodic service remains available independently.

Explicit native/protocol detach and due expiry cancel both held and unheard released intent through the existing runtime cleanup, without consuming event slots, waiting for audio, changing scalar settlement/history or cancelling structural work. A service pass scans at most 16 attachment records. Ordinary mapping/undo preserves held records and their original generations/activity; accepted external restore clears press/activity state in the same control operation, while failed, Busy or invalid restore preserves it. No note policy is serialized. Actual host timer/callback scheduling and semantic WebView disposal remain facade proof; this controller boundary alone does not complete task 3.3.

### Preserve admitted structural work across editor loss

The format-neutral controller first exposes a bounded take-preparation, submit-completion and service boundary over the existing session's one active request and 128 retained outcomes. Preparation/completion wrappers retain private controller/native-request authority and own their work; they move to a real worker without borrowing an editor. A foreign or duplicate completion is rejected while returning ownership and preserving the genuine pending work. Live sealed protocol context supplies the real native attachment for snapshot, parameter, structural and status operations; mutable public correlation fields are not authority. Native undo admission reuses the session's existing implementation. Known request-status recovery, rather than replaying undo against changed history, retrieves its terminal outcome.

Main/control service performs at most one retirement reclamation and one ready completion per call. After off-audio reclamation, the exclusively borrowed runtime's activation readiness decides whether publication can proceed. A busy slot keeps the prepared job running and owned; never call session completion speculatively because it retains activation failures as terminal outcomes. Preflight JavaScript-safe next generation before publication. A successful structural publication balances all retiring parameter gestures using their already reserved End capacity, advances document generation and preserves scalar values and applied/admitted parameter sequences. Deferred or failed work preserves the current gestures, generation and accepted document/history. Unknown or evicted job status is an explicit error, never invented running/success state.

The take/submit component is followed by an actual bounded worker owned by the persistent instrument host, with startup/shutdown/panic and editor-loss proof. It is not owned by Wry or a format-specific editor. Concrete host servicing must wake both for completed preparation and later runtime capacity after deferral, independently of a destroyed editor's GTK timer. These worker/wake and actual frontend recovery gates remain open until their tests pass; explicit test-driven servicing at the component boundary does not claim automatic product progress or complete task 3.3.

### Start persistent preparation before acknowledging structural work

Main uses nonblocking operations; the idle worker may wait for work, then requests service after inserting its completion. One main service call drains at most one completion and performs the existing bounded publication step. A zero-sized thread-affinity marker keeps the controller on its constructing control thread; the native facade must construct it on the actual host main thread.

Editor detach never stops this worker. Unexpected worker termination is a fatal service-unavailable condition that preserves accepted state/audio; it must not fabricate a native outcome or report a permanently running job as healthy. Internal panic recovery and arbitrary I/O cancellation are not promised. Busy completion remains owned without a wake loop; the facade later routes the real runtime swap report to another main service opportunity. Core scheduler tests are distinct from actual CLAP callback proof.

## Risks / Trade-offs

- **Wry/GTK main-thread constraints conflict with CLAP host behavior** → store the WebView only in the plugin main-thread object, use the host loop, assert callback thread identity and reject creation when the contract cannot be met.
- **A runtime replacement could be dropped on audio** → use capacity-proved bidirectional slots, prohibit a second activation until retirement is reclaimed and add an allocation/destructor sentinel test.
- **IPC scope grows toward a second backend implementation** → expose only methods required by mapped scenarios and keep unsupported Trigger operations explicit.
- **CLAP host callbacks differ between the synthetic host and a DAW** → exercise the official validator where applicable and retain named-DAW acceptance as a separate required gate.
- **Linux child WebView behavior differs under Wayland** → claim X11 only and fail unsupported APIs explicitly.
- **Resource lookup accidentally depends on the checkout** → run the acceptance binary and resources from a temporary external tree after hiding source asset paths from the process.
